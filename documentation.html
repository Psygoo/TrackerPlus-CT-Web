An unofficial firmware mod for Polyend Tracker+.

Open the Web Patcher

USE AT YOUR OWN RISK. Song Mode is NOT YET HARDWARE-VALIDATED.

Choose or drop your own original Tracker+ 1.2.0 PTF. Processing happens locally in your browser, with no uploads. Save the verified result as TrackerPlus_1.2.0_CT.ptf. Installation is a separate manual decision.

The six conditions are 1:2, 2:2, 1:4, 2:4, 3:4 and 4:4. Expanded cycle conditions through 8:8 and 1st / Not First, PRE / Not PRE, NEI / Not NEI are future research goals, not implemented or promised features. Exact behaviour, track-neighbour relationships, timing and feasibility require Tracker+ hardware validation.

GitHub hosts the static website assets; firmware is never sent to GitHub. GitHub Pages logs visitor IP addresses for security. Ko-fi and other external links open only when selected. The development repository remains private; the GitHub navigation link opens the developer profile.

RECOVERY.md

# Installation preparation and recovery limits

This is experimental, unofficial firmware. Before installation, verify exact Tracker+ model, input/output hashes and a full independent SD backup, including Workspace, hidden files and projects. Test the backup and keep the unmodified stock PTF accessible from a computer. Do not use original projects for initial tests.

Normal update: follow the official Tracker+ manual, Config → Firmware, and explicitly select the locally generated file. Use stable power; do not interrupt the update. Check hashes after copying to SD and eject it correctly. This repository does not control the device or perform updates.

The official Tracker+ manual, section 13.3, page 318 documents microSD/pinhole recovery using the recessed button near USB with the unit powered. Read the actual manual before using it. Recovery may select a firmware file at random: prepare `/Firmware` with **only the verified stock Tracker+ PTF eligible** before attempting it. Keep the candidate out of that folder during recovery. Restricting the folder to one verified stock file is this project's precaution to avoid random selection of a modified candidate; the manual itself discusses retaining multiple official releases. Do not substitute instructions for Tracker original or Mini, or assume USB recovery support from those products.

The PTF application image does not include the bootloader. Static inspection and earlier upstream recovery observations do not prove bootloader revision, erase protection, power-loss resilience or successful recovery from every early failure. Recovery does not restore project data or guarantee erasure of appended application bytes. A working user installation does not remove these limits. If the documented mechanism fails, preserve logs and seek applicable Polyend support rather than repeatedly improvising recovery steps.

Stop before installation if hashes or backup verification fail, model/firmware is uncertain, or stock recovery preparation is unavailable. Stop functional testing on reboot loops, freeze, data damage or incorrect deterministic passages. Update progress alone provides no safe timeout for cutting power.

This standalone repository deliberately does not copy the source repository's Git history, unrelated patches, projects or binary artifacts.

Reused components:

- `tools/ptf.py`: Intel HEX/PTF parsing and deterministic serialization.
- `tools/patch_ptf.py`: placement, RAM allocation, relocations and existing patch formats, plus the locally validated inline-hook extension.
- `tools/emu/machine.py`, `fakefs.py`, `seq_timing.py`: the existing Unicorn Machine, overlay filesystem and sequencer fixtures. seq_timing came from the companion Modular-Trackular upstream checkout; this is not a second emulator. Companion checkout commit: `ac584b93304672eaa78103b1a15db934c89dfcde`.
- `patch/community_beta/payload.py`: minimal extraction of the existing Conditional Trigs ARM emitters (original six-condition wrappers, UI, atomic transport and swap), preserving their emitted bytes.
- `tests/community_beta_arm.py`: preserved historical expanded-condition harness, excluded from CT6 validation; portable extraction of existing stock-gate, UI and Pattern/Song tests; fixture imports are rebound to this repository. No functional ARM changes are introduced.
- `tools/test_inline_hooks.py`: host-side patcher tests, using synthetic guards rather than embedded stock windows.

The firmware input, generated PTF, original instruction windows, dumps, SD contents and raw local test artifacts are excluded. Hook metadata contains addresses and SHA-256 fingerprints, not the original firmware windows; the patcher obtains those windows from the user's input. Payload source generates our patch code and replays the small displaced instruction sequences required by the hooks; it does not embed stock functions or firmware dumps. The MIT license is not a license to Polyend's firmware. No claim is made here about redistribution rights for generated firmware.

Browser Phase 1 additions port the existing MIT PTF/inline-hook logic and generate a source representation of the original MIT CT6 patch program without reading firmware. The fixed program includes only project patch code and the same small displaced-instruction replays already in the original emitter. All hook originals are still obtained from the user's input.
