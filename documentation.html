Tracker+ Conditional Trigs — CT2

An independent, unofficial modification for Polyend Tracker+ (2024 plus model), using original firmware 1.2.0. Not affiliated with, endorsed by or supported by Polyend. Not for Tracker Mini or the original Tracker.

Public firmware identifier: 1.2.0-CT2 / Build 1504. Release: v0.2.1-CT2. Use the public web patcher to generate your firmware locally from the supported original input.

CT2 uses the exact hardware-validated H13 implementation, including the NE/!NE → PR/!PR correction. Only its displayed version label changes. The user confirmed H13 works on physical Tracker+ hardware, specifically including that fix. The project owner also installed and confirmed the final CT2 firmware works correctly on physical Tracker+ hardware. These reports do not establish that every hardware mode or configuration has been tested.

Corrected PRE after NE

NE and !NE now update their own track's PRE history with the evaluated logical conditional-note result, including both acceptance and rejection. A later PR follows that result; !PR inverts it. Micro-move changes dispatch timing without changing the recorded logical result. Neighbour chains continue to work, using the immediately preceding track's last conditional-note result. PR/!PR remain PRE non-producers. An event containing PR/!PR retains previous PRE even when NE is in the other FX column; both columns read before commit. Full semantics and examples.

CT2 is the corrected successor to the superseded H12 public release, v0.2.0-h12. H12 did not update PRE after NE/!NE. Its release, source and tag remain available for reference/recovery; the default web patcher now targets CT2. CT6 is preserved at archive/ct6-before-h12.

Chance and Fill

Percentages 0–100; ratios 1:2 through 8:8; FIRST 1S / !1S; PRE PR / !PR; NEI NE / !NE. Exact encoder order in both directions:

0–100 → 1:2, 2:2, 1:3, 2:3, 3:3 … 1:8 … 8:8 → PR → !PR → NE → !NE → 1S → !1S

Ratios are ordered by denominator 2–8, then numerator 1–denominator. Existing stored IDs are unchanged. Fill FX1 and FX2 retain Constant, From-To and Random with all percentages and conditions, using the same logical order and endpoint controls. Try 1:4 for a four-pass phrase or Random PR → !NE to choose among PR, !PR, NE and !NE. Condition guide.

Chance conditions

Enter Chance (C) in FX1 or FX2. The value field uses the labels below, rather than internal IDs. Both columns and Fill use the same logical encoder order:

0–100 → 1:2, 2:2, 1:3 … 8:8 → PR → !PR → NE → !NE → 1S → !1S

Ratios are ordered by denominator 2–8, then numerator 1–denominator.

PRE history

Percentage values 0–100 and ratio/FIRST values 101–137 retain their existing PRE producer behavior: final combined condition acceptance is recorded after evaluation. NE/!NE now also produce PRE, using the final logical conditional- note result: accepted conditions AND a valid note trigger. A rejected NE, or one evaluated without a valid note, records false. A later PR follows it and !PR inverts it. This corrects the H12 bug and is hardware-confirmed in H13.

PR/!PR never produce PRE. Any event containing PR or !PR leaves PRE unchanged, including when another producer or NE is in the other column. An NE+NE or NE+base event without PR records its final combined logical note result once. Both columns see the same prior history before that commit; stock evaluates FX2 then FX1. PR on the same row as NE sees the previous PRE, not a partial current-row result.

Plain notes, empty rows and skipped evaluations retain history. PR always reads its own track. Reset clears PRE to false, making PR reject and !PR pass until a producer. Base producers keep their previous handling of FX-only conditions; NE specifically uses logical note validity, as described below.

Example: put a 50% Chance hit on row 01, PR on row 03 and !PR on row 05 of one track. The PR hit follows an accepted percentage event; !PR follows a rejected one. The consumer rows do not replace the percentage event's PRE history.

Example after NE: track 1 row 01 has note + 1S. Track 2 has note + NE on row 03, PR on row 05, !PR on row 07. First pass: NE and PR play; !PR rejects. Later passes: NE and PR reject; !PR plays. Replace NE with !NE and the source outcome reverses while PR still follows the evaluated !NE result. Micro-move and ordinary notes between those rows do not change which PRE result the consumers read.

Neighbour results, across rows

NE reads the last evaluated conditional-note result on the immediately preceding track, whether on an earlier row or the same row. It uses logical acceptance/scheduling, not the exact audible dispatch time. Micro-move changes sound timing without changing that logical result. PR/!PR, NE/!NE, percentages, FIRST and ratios can all produce neighbour results, enabling chains.

An evaluated conditional event records true only if its combined conditions pass and it has a valid note trigger. Rejection records false. A condition on an FX-only/invalid-note event cannot record a successfully played note. Empty rows and ordinary notes do not replace the last conditional result. A muted or disabled track that stock processing skips does not evaluate a condition and retains its prior result; NE does not measure mixer output, volume or audibility. These edge cases were checked offline, not individually hardware-certified. Track 1 has no neighbour: NE rejects and !NE accepts. There is no wraparound.

Example on different rows: track 1 row 01 has note + 1S; track 2 row 03 has note + NE; track 3 row 05 has note + !NE. On the first pass tracks 1 and 2 play; on later passes track 3 plays. The same logical result holds on the same row and with Micro-move. Tracks are evaluated in their established order; a later track can observe the preceding track's newly evaluated conditional result.

Loops retain results. Transport restart, preview/count-in reset and global pattern changes clear histories; queued per-track pattern changes clear that track's result when consumed. Song/performance modes, complex routing and every transport combination have not all been separately hardware-tested.

Fill FX1 and FX2

Use the stock three modes and endpoint fields. Select Chance explicitly.

  • Constant: any percentage or condition, for example C50, C1:4, CPR, CNE, C!1S. Every eligible row receives that stored condition.
  • From-To: interpolate across logical positions, then encode to existing condition IDs. Stock binary32 interpolation and integer truncation remain. Six selected rows from 0 to 59 produce 0, 11, 23, 35, 47, 59. Reversing endpoints reverses direction; one row uses the first endpoint. Skipped rows retain stock interpolation positions. Try 1:2 → 4:4, PR → !NE, or mixed 50 → 1S.
  • Random: the existing min/max controls select an inclusive logical interval. Reversed bounds are sorted. Stock PRNG/modulo and draw order remain; equal bounds still consume a draw. PR → !NE chooses PR, !PR, NE or !NE; 0 → !1S includes all 142 values. Percentage-only ranges preserve stock generation exactly. No condition is automatically excluded.

Other FX and the stock Random-FX-type option keep their previous behavior. There is no new Fill mode. Stored IDs: percentages 0–100; 1S/!1S 101/102; ratios 103–137; PR/!PR 138/139; NE/!NE 140/141.

This independent project is not affiliated with Polyend. Read the disclaimer, compatibility guide and recovery procedure before making changes.

  • Obtain the official Polyend Tracker+ 1.2.0 PTF from Polyend's Tracker+ downloads. Extract the PTF if delivered in an archive.   • Back up the entire SD card, including Workspace, projects, samples and settings, to a separate device. Keep untouched project copies, the original official firmware and a known working recovery image. Review CT6 migration before playing older conditional projects.
  • Open the reviewed web patcher on HTTPS, or serve this source locally with node tools/serve.mjs. Select/drop your own original PTF. Processing stays in browser memory; no upload occurs. Wait for successful verification.
  • Save TrackerPlus_CT2.ptf. Its required SHA-256 is baa93d46208c0f6ab2ca0c7507fb3c430703a3ceada582a780779844a0d03b20. A hash mismatch or error means do not install.   • Follow the official manual's firmware update procedure: copy the generated PTF into the SD card's Firmware folder, safely eject, insert in Tracker+, then select the file under Config → Firmware and follow device prompts. Use reliable power and do not interrupt the update. The website never flashes a device or edits your SD card.
  • Confirm 1.2.0-CT2 / Build 1504, then test a copied project. Check the conditions and Fill modes you use before committing important work.

Manual reference: Polyend Tracker+ manual, firmware update/recovery. To return to official firmware, use its normal update procedure when available, or read recovery. Restoring firmware does not migrate projects.

Recovery and returning to stock

Keep an untouched official Tracker+ 1.2.0 PTF and a separate SD/Workspace/project backup before installing. Recovery is not guaranteed by this project.

If the device still opens Config, follow the official normal update process using official firmware. If it does not boot normally, consult section 13.3 of the official Tracker+ manual and follow Polyend's recovery instructions for the pinhole recovery button near USB while powered on. The manual describes recovery searching the Firmware folder and selecting a firmware file. Because that selection can be arbitrary, prepare a recovery SD card with only the verified official stock PTF eligible in Firmware; do not leave multiple modified images there. This is a project precaution, not an additional official guarantee.

Use firmware for the exact Tracker+ model, reliable power and the official procedure. If recovery fails, use Polyend support. A firmware rollback does not restore or migrate project data: use backed-up copies appropriate to that firmware. Do not overwrite the only copy of a project.
